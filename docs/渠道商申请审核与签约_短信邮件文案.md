> - 版本：v1.1
> - 更新日期：2026-07-29
> - 适用范围：营销 H5 提交申请 → 运营审核并维护渠道码 → 发起电子签约 → 完成签约
> - 语言范围：中国大陆手机号使用简体中文；中国香港手机号使用繁体中文。

## 一、流程和通知节点

| 节点 | 系统状态 | 用户通知 | 运营通知 | 主要目的 |
|---|---|---|---|---|
| 提交申请 | 待审核 | 邮件回执；原则上不发短信 | 邮件 | 告知运营有新申请需要处理 |
| 审核驳回 | 已驳回 | 邮件 + 短信 | 后台留档 | 告知结果和可申诉方式 |
| 审核通过 | 待签约 | 邮件 + 短信 | 邮件 + 短信 | 通知双方发起电子签约 |
| 签约过期 | 签约过期 | 邮件 + 短信 | 后台待办 | 告知原签约入口失效，可由运营重新发送邀请 |
| 签约完成 | 已签约 | 邮件 | 后台状态；可选邮件 | 发送协议、渠道码和后续入口 |

### 核心必发通知

以下三组通知对应当前确认的业务流程，必须实现：

1. H5 提交申请后：向运营人员发送 `EMAIL-OPS-001`。
2. 审核通过并发起电子签约后：
   - 向用户发送 `EMAIL-CH-003` 和 `SMS-CH-003`，系统根据手机号归属选择 `.zh-CN` 或 `.zh-HK` 版本；
   - 向负责运营发送 `EMAIL-OPS-002` 和 `SMS-OPS-001`。
3. 电子签约完成后：向用户发送 `EMAIL-CH-004`，系统根据手机号归属选择 `.zh-CN` 或 `.zh-HK` 版本。

审核驳回和签约过期模板属于完整业务闭环的建议配置，可根据首期范围启用。

### 推荐状态流

```text
待审核
├─ 已驳回
└─ 审核通过 → 待签约
                  ├─ 签约过期 → 重新发送邀请后回到待签约
                  └─ 签约完成 → 已签约
```

## 二、短信合规及送达率优化原则

### 2.1 短信类型

本流程短信应申报为“通知短信”，只发送给主动提交申请且需要接收业务进度的用户。短信中不得加入产品介绍、招商招募、佣金比例、优惠、加盟、返利或引导推广等内容。

运营商和云短信平台可能按照正文而不是业务方主观分类进行判断，因此：

- 短信只描述“申请、审核、协议、状态变化”。
- “渠道商、招商、招募、推广、佣金、返利、注册公司、财税服务”等词不进入短信。
- 渠道码、驳回原因、资料清单、签约链接和合同内容放在邮件中。
- 短信不使用感叹号、表情符号、特殊符号或夸张词。
- 短信不放动态短链接，不放 IP 地址，不放个人手机号、微信号或 QQ。
- 如确需短信链接，只使用已经备案并通过模板审核的固定 HTTPS 域名；本流程首选“请查看预留邮箱”，不在短信中放链接。

### 2.2 短信签名

推荐申请并报备：

```text
【利柏思商务】
```

原因：

- 与“利柏思商务服务（上海）有限公司”存在清晰、连续的名称关系。
- 中文主体比单独使用英文品牌更容易向用户解释真实发送方。
- 最终是否可以使用，仍以短信平台资质审核和运营商实名报备结果为准。

备选签名：

```text
【利柏思商务服务】
```

如 `Leapex利柏思` 已取得商标或具备相应品牌证明，可另行申请：

```text
【Leapex利柏思】
```

### 2.3 频次和时间

- 普通通知发送窗口：每日 `09:00–20:30`，以接收人所在地时区为准。
- 同一手机号同一内容 30 秒内不重复发送。
- 产品侧建议限制为同一手机号每天最多 2 条本流程短信。
- 运营人员短信也计入运营商频控，不应以短信代替后台待办。

### 2.4 用户授权建议

营销 H5 提交按钮上方建议保留以下告知，并记录版本、时间、手机号、IP 和勾选状态：

```text
提交后，Leapex利柏思将通过短信和邮件向您发送申请审核、电子签约及合作状态通知。
```

该告知只授权本次申请相关的服务通知，不等于授权发送营销短信。

### 2.5 模板变量

腾讯云短信模板使用 `{1}`、`{2}` 这类连续编号变量。为了提高审核和送达成功率，短信变量应尽量少：

| 变量 | 用途 | 规则 |
|---|---|---|
| `{1}` | 签署截止时间 | 建议固定格式 `7月31日18:00` |
| `{2}` | 可选的申请尾号 | 仅使用 4 位数字；非必要不使用 |

姓名、完整申请编号、渠道码、链接、驳回原因和资料清单不作为短信变量。

### 2.6 手机号归属与语言路由

用户通知以提交申请时验证通过的手机号国家或地区代码作为语言选择依据。短信和邮件必须使用同一语言版本，不允许分别判断。

| 手机号 | `notification_locale` | 短信通道 | 用户短信与邮件语言 |
|---|---|---|---|
| `+86` 开头 | `zh-CN` | 中国大陆短信通道 | 简体中文 |
| `+852` 开头 | `zh-HK` | 中国香港短信通道 | 繁体中文 |

路由规则：

1. 手机号在提交申请时统一转为 E.164 格式并保存，例如 `+8613812345678`、`+85291234567`。
2. `+86` 号码调用模板编号后缀为 `.zh-CN` 的简体模板。
3. `+852` 号码调用模板编号后缀为 `.zh-HK` 的繁体模板。
4. 邮件语言跟随手机号归属：香港手机号即使填写了中国大陆邮箱，也发送繁体中文邮件。
5. 手机号缺少国家或地区代码、格式无效或不属于当前支持范围时，不得猜测语言；通知任务进入异常队列，由运营补全号码后重试。
6. 运营人员内部通知 `SMS-OPS-*`、`EMAIL-OPS-*` 不跟随申请人手机号切换，统一使用简体中文。
7. 通知记录需保存 `phone_e164`、`phone_region`、`notification_locale`、`template_id` 和 `template_version`，用于审计和问题追踪。

模板版本示例：

```text
SMS-CH-003.zh-CN
SMS-CH-003.zh-HK
EMAIL-CH-003.zh-CN
EMAIL-CH-003.zh-HK
```


建议：

- 发件域名配置 SPF、DKIM 和 DMARC。

## 七、发送和去重规则

### 7.1 推荐触发顺序

#### 申请提交

1. 写入申请记录。
2. 将手机号标准化为 E.164 格式，识别 `phone_region` 并写入 `notification_locale`。
3. 向运营发送 `EMAIL-OPS-001`。
4. 根据 `notification_locale` 向用户发送 `EMAIL-CH-001.zh-CN` 或 `EMAIL-CH-001.zh-HK`。
5. H5 展示成功页面。
6. 不默认发送 `SMS-CH-001`；如启用，同样根据 `notification_locale` 选择对应语言版本。

#### 审核通过

1. 运营在后台确认渠道码。
2. 系统创建电子协议和唯一签约入口。
3. 状态由“待审核”改为“待签约”。
4. 根据 `notification_locale` 向用户发送 `EMAIL-CH-003.zh-CN` 或 `EMAIL-CH-003.zh-HK`。
5. 邮件进入发送队列后，使用相同的 `notification_locale` 发送 `SMS-CH-003.zh-CN` 或 `SMS-CH-003.zh-HK`。
6. 向运营发送 `EMAIL-OPS-002` 和 `SMS-OPS-001`。

#### 签约过期与重新发送

1. 到达签署截止时间后，系统确认协议尚未完成双方签署。
2. 原电子签入口失效，状态由“待签约”改为“签约过期”。
3. 根据 `notification_locale` 向用户发送对应的 `EMAIL-CH-005` 和 `SMS-CH-004` 语言版本，并在运营后台生成待办。
4. 运营核对用户邮箱、手机号及合同主体后，可在后台选择“重新发送电子签邀请”。
5. 系统创建新的签约入口和事件版本，状态由“签约过期”恢复为“待签约”。
6. 向用户重新发送与当前 `notification_locale` 一致的 `EMAIL-CH-003` 和 `SMS-CH-003`；原签约入口继续保持失效，仅最新邮件中的入口有效。

#### 签约完成

1. 校验电子签名平台回调签名和幂等键，并确认用户与我方均已签署。
2. 保存已签协议和协议编号。
3. 状态由“待签约”改为“已签约”。
4. 启用正式渠道码和渠道商工作台账号。
5. 根据 `notification_locale` 向用户发送 `EMAIL-CH-004.zh-CN` 或 `EMAIL-CH-004.zh-HK`。
6. 在运营后台生成“签约完成”记录；如需要邮件通知运营，发送 `EMAIL-OPS-003`。

签约完成默认不再发送短信，以减少同日触达次数和运营商拦截风险；用户以邮件中的已签协议和渠道码作为正式结果凭证。

### 7.2 幂等和防重

建议幂等键：

```text
{{event_name}}:{{application_no}}:{{event_version}}
```

规则：

- 同一幂等键只允许生成一次通知任务。
- 重新发送签约邀请时必须递增 `event_version`，不得复用过期邀请的通知任务或签约入口。
- 同一业务事件的邮件和短信必须读取同一份 `notification_locale` 快照，避免用户收到简繁混合通知。
- 用户修改手机号并跨地区变更时，只影响变更后的新通知；已经生成的通知任务不自动切换语言。
- 邮件和短信分别记录 `queued / sent / delivered / opened / clicked`。

### 7.3 上线前语言验收

每个用户通知节点至少覆盖以下测试：

| 测试号码 | 预期邮件 | 预期短信 |
|---|---|---|
| `+8613812345678` | `.zh-CN` 简体版 | `.zh-CN` 简体版 |
| `+85291234567` | `.zh-HK` 繁体版 | `.zh-HK` 繁体版 |
| 无国家或地区代码 | 不发送，进入异常队列 | 不发送，进入异常队列 |

验收要求：

- 繁体模板不得出现“申请、审核、通过、邮箱、短信、签约、渠道码、运营”等简体词形。
- 香港模板统一使用“電郵”“短訊”“聯絡”“營運”等香港地区用语。
- 公司、协议、渠道码、申请编号等变量值保持原始数据，不对姓名或企业法定名称进行自动简繁转换。
- 邮件主题、预览摘要、正文和页脚的语言必须一致。
- 短信签名、正文模板和发送通道必须与号码地区匹配。

## 十、规则依据

1. 工业和信息化部《通信短信息服务管理规定（2026年修订）》：要求真实、清晰标识发送方身份；商业性短信息需要用户同意，并提供有效拒收方式；通信短信息内容及同意证明材料需要按规定留存。  
   <https://www.miit.gov.cn/zcfg/xxtxl/art/2026/art_20183ad07ad740f7b59bb5b1212df241.html>

2. 腾讯云《短信签名审核标准》：国内短信签名需符合企业或品牌证明要求，签名报备结果会影响实际发送。  
   <https://cloud.tencent.com/document/product/382/39022>

3. 腾讯云《正文模板审核标准》：通知短信不得包含营销推广内容或营销链接；短信内容、变量、特殊符号和链接均受限制；“招商、招募、加盟、返利、注册公司推广、财税推广”等内容属于高风险或禁止范围。  
   <https://cloud.tencent.com/document/product/382/39023>

4. 腾讯云《配置基础信息》：平台和运营商均存在发送频率限制，应在产品侧设置更严格的频控与状态回调。  
   <https://cloud.tencent.com/document/product/382/37809>

> 注意：短信平台和运营商规则可能动态调整。上线时应以所选短信服务商控制台的最新审核反馈为准，并预留不通过短信、改由邮件和后台待办兜底的方案。
