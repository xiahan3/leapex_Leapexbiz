# 老客首页 · 待办事项 展示规则与场景枚举

> 适用：Leapex 利柏思微信小程序 · 老客首页「待办事项」模块
> 当前版本：V2.0
> 更新日期：2026-07-31
> 关联页面：账单支付、服务信息填写、KYC 认证、年审服务、订单详情、我的公司

---

## 一、最新规则结论

老客首页仅展示“当前必须由用户继续完成”的待办，共保留以下 **3 类、4 个场景**：

1. **订单待办**
   - 订单未支付。
2. **服务流程待办**
   - 服务信息未填写完成。
   - KYC 未完成。
3. **公司待办**
   - 公司年审已经过期。

除上述场景外，不再生成或展示其他首页待办。

---

## 二、模块目标

待办事项模块只回答两个问题：

1. 用户现在是否有必须继续完成的动作？
2. 点击后应进入哪个页面继续办理？

模块不承担以下职责：

- 不展示服务办理进度。
- 不展示人工审核状态。
- 不展示成功、失败或驳回结果通知。
- 不展示营销、卡券、交付物等信息。
- 不承担临期提醒、重复催办或消息历史展示。

上述内容分别由订单详情、服务详情、消息中心等模块承接。

---

## 三、待办数据模型

```text
Todo {
  id              // 待办唯一标识
  type            // 场景枚举，见第五章
  companyId       // 关联公司 ID，可空
  companyName     // 公司名称
  orderNo         // 关联订单号，可空
  serviceId       // 关联服务实例 ID，可空
  serviceName     // 服务名称，可空
  title           // 主文案
  desc            // 副文案
  icon            // Tabler 图标
  tone            // orange | blue | red
  target          // 点击跳转页面与参数
  createdAt       // 待办生成时间
  dueAt           // 年审过期时间等业务期限，可空
  resolveOn       // 自动消解条件
}
```

待办由订单、服务实例、KYC 和公司年审状态实时计算，不由运营人员手工创建。

## 四、生成与消解规则

### 4.1 订单待办：未支付

**生成条件**

- 订单已创建；
- 订单应付金额大于 0；
- 支付状态为 `unpaid`、`pending` 或支付未完成；
- 订单未取消、未关闭、未退款。

**展示内容**

- 标题：`订单待支付`
- 副文案：`{订单号} · {服务名称} · {应付金额}`
- 点击：进入该订单的账单支付页。

**消解条件**

- 支付成功；
- 订单取消或关闭；
- 订单被作废；
- 应付金额调整为 0。

**统一口径**

- 支付失败、用户主动中断支付等情况仍归入 `order_unpaid`。
- 不再单独生成“支付失败”“回单待确认”“重新支付”等待办。
- 银行回单已提交但尚未确认到账时，支付状态仍未完成，可继续保留同一条未支付待办，不生成第二条。

### 4.2 服务流程待办：信息未填写

适用于所有需要用户填写办理信息的服务，包括但不限于公司注册、年审、工商变更、记账报税、商标和地址服务。

**生成条件**

- 服务实例已经进入用户信息填写阶段；
- 该服务配置 `requires_info = true`；
- 必填信息未提交完成；
- 服务未取消、未关闭、未完成。

**展示内容**

- 标题：`服务资料待填写`
- 副文案：`{公司名称} · {服务名称}`
- 点击：进入该服务第一个未完成的信息填写步骤。

**消解条件**

- 用户提交完整办理信息；
- 服务取消或关闭；
- 服务实例作废。

**统一口径**

- 一个服务即使缺少多个字段，也只生成一条 `service_info_pending`。
- 不按字段生成“补充地址证明”“补充身份证”“补充公司资料”等独立待办。
- 信息被人工退回、审核失败等状态不在首页生成新的待办类型；相关原因在服务详情或消息中心展示。

### 4.3 服务流程待办：KYC 未完成

适用于所有配置了 KYC 要求的服务。

**生成条件**

- 服务配置 `requires_kyc = true`；
- KYC 状态为 `not_started`、`in_progress` 或 `action_required`；
- 服务未取消、未关闭、未完成。

**展示内容**

- 标题：`KYC 待完成`
- 副文案：`{公司名称} · {服务名称}`
- 点击：进入 KYC 第一个未完成步骤。

**消解条件**

- KYC 已完成提交并进入 `submitted` 或 `reviewing`；
- KYC 已审核通过；
- 服务取消或关闭。

**统一口径**

- 同一服务只生成一条 `service_kyc_pending`。
- KYC 有多个参与人或多个未完成步骤时，不拆成多条待办。
- KYC 被退回并重新进入用户处理状态时，仍使用统一标题“KYC 待完成”，不生成“KYC 未通过”“补充 KYC 资料”等新类型。
- KYC 已提交、正在人工审核时不展示待办。

### 4.4 公司待办：年审已过期

**生成条件**

- 当前时间晚于公司年审业务截止时间 `annual_due_at`；
- 本年度年审尚未完成；
- 公司状态不是已注销、注销中或已关闭。

**展示内容**

- 标题：`公司年审已过期`
- 副文案：`{公司名称} · 已过期 {N} 天`
- 点击：进入年审服务详情或该公司的年审办理入口。

**消解条件**

- 本年度年审服务完成；
- 后台将本年度年审状态更新为已完成；
- 公司进入注销或关闭状态。

**统一口径**

- 年审到期前不生成首页待办。
- 去掉 T-90、T-60、T-30、T-7 等多轮首页待办。
- 不展示“距到期 N 天”“第 N 轮提醒”等临期内容。
- 已购买年审服务但尚未完成时，可继续保留过期待办；点击后进入对应年审服务进度。

## 六、排序、聚合与去重

### 6.1 排序

首页按以下顺序展示：

1. `order_unpaid`
2. `service_info_pending`
3. `service_kyc_pending`
4. `company_annual_overdue`

同类型存在多条时：

- 订单待支付：按订单创建时间升序，较早订单优先。
- 服务资料/KYC：按进入待处理状态时间升序。
- 年审过期：按过期天数降序，过期最久的公司优先。

### 6.2 去重

- 同一订单最多一条未支付待办。
- 同一服务最多一条资料待填写待办。
- 同一服务最多一条 KYC 待完成待办。
- 同一公司同一年度最多一条年审过期待办。
- 同一服务的资料待填写与 KYC 待完成可以同时存在，因为二者对应不同用户动作。

### 6.3 展示上限

- 首页默认最多展示 6 条。
- 标题右侧显示实际待办总数，例如：`共 4 项`。
- 超过 6 条时，首页展示前 6 条，并提供“查看全部待办”入口。

## 七、页面展示规范

每条待办采用统一结构：

```text
[图标] 主文案                       [分类标签] >
       公司 / 订单 / 服务说明
```

分类标签固定为：

- 订单：`订单`
- 服务资料与 KYC：`服务`
- 年审过期：`公司`

交互规则：

- 整行可点击。
- 点击直接进入可继续操作的页面，不先经过无操作能力的详情页。
- 对应动作完成后返回首页，待办自动消失并更新总数。
- 不提供“忽略”“稍后处理”或手动删除。

## 八、状态流转

### 8.1 单个订单与服务

```text
订单创建
  └─ 支付未完成
       └─ [订单待支付]
            └─ 支付完成 → 待办消失

进入服务信息填写阶段
  └─ 必填信息未提交
       └─ [服务资料待填写]
            └─ 信息提交完成 → 待办消失

服务要求 KYC
  └─ KYC 未开始 / 进行中 / 需用户处理
       └─ [KYC 待完成]
            └─ KYC 提交 → 待办消失

服务进入人工审核或办理阶段
  └─ 首页不生成待办，进度在服务详情中展示
```

### 8.2 公司年审

```text
未到期
  └─ 首页不生成待办

超过 annual_due_at 且本年度未完成
  └─ [公司年审已过期]
       └─ 年审完成 / 公司注销关闭 → 待办消失
```

## 九、明确排除的待办

以下场景不得在老客首页生成待办：

| 排除场景 | 承接位置 |
|---|---|
| 支付失败、支付中断、重新支付 | 统一归入“订单待支付” |
| 银行回单待确认 | 订单详情 / 账单页 |
| 核名失败、核名通过 | 核名结果页 / 消息中心 |
| KYC 审核中、审核通过 | KYC 详情 / 消息中心 |
| KYC 未通过、补充地址证明、补充 KYC 资料 | 统一归入“KYC 待完成”，不新增类型 |
| 服务资料被退回、人工预审退回 | 服务详情 / 消息中心 |
| 待签字、待回寄文件 | 服务详情 |
| 政府审批中、服务办理中 | 订单详情 / 服务进度 |
| 交付物已就绪 | 交付物中心 / 消息中心 |
| 年审临期、记账报税临期、PTR 临期 | 不进入老客首页待办 |
| 商标续期、BR 续期、证件到期 | 对应服务页或消息中心 |
| 公司档案不完整 | 我的公司 |
| 卡券、优惠、营销活动 | 卡券中心 / 营销页面 |

## 十、空状态

当所有待办均已消解时：

- 标题显示：`待办事项`
- 数量显示：`共 0 项`
- 内容显示：`✓ 暂无待办`
- 不显示营销推荐或其他替代内容。

## 十一、与其他模块的关系

| 模块 | 关系 |
|---|---|
| 订单列表 / 订单详情 | 承接订单状态、支付结果、办理进度和异常说明。 |
| 服务详情 | 承接人工审核、资料退回、签字、政府审批、交付等中间状态。 |
| KYC | 待办只判断用户是否完成提交；人工审核状态不生成首页待办。 |
| 我的公司 | 提供公司状态、年审信息和公司档案。 |
| 消息中心 | 保存状态通知历史；消息是否发送不决定待办是否存在。 |
| 管理后台 | 后台更新订单、服务、KYC 和年审状态后，服务端重新计算用户待办。 |

## 十二、接口与计算建议

首页接口建议直接返回计算后的待办：

```json
{
  "total": 4,
  "items": [
    {
      "id": "todo_order_ORD-2026-0205",
      "type": "order_unpaid",
      "title": "订单待支付",
      "desc": "ORD-2026-0205 · 新设香港本地有限公司 · HKD 5,533",
      "target": {
        "page": "/pages/bill/pay",
        "params": {
          "orderNo": "ORD-2026-0205"
        }
      }
    }
  ]
}
```

服务端要求：

- 每次查询基于最新业务状态计算，不依赖前端缓存中的旧待办。
- 状态更新后保证待办最终一致。
- 使用稳定业务键去重，例如 `type + orderNo/serviceId/companyId + 年度`。
- 已取消、关闭、作废、完成的业务不得继续返回待办。

## 十三、验收清单

- [ ] 老客首页只出现 4 个允许的 `type`。
- [ ] 未支付订单只生成一条“订单待支付”。
- [ ] 支付失败不会新增另一种待办。
- [ ] 所有需填写信息的服务均可生成“服务资料待填写”。
- [ ] 一个服务缺少多个字段时仍只展示一条资料待办。
- [ ] 所有需 KYC 的服务均可生成“KYC 待完成”。
- [ ] KYC 已提交、审核中或已通过时不展示 KYC 待办。
- [ ] 年审未过期时不展示年审待办。
- [ ] 年审已过期且未完成时展示“公司年审已过期”。
- [ ] 点击每条待办均直达对应操作页面。
- [ ] 完成支付、资料填写或 KYC 提交后，对应待办自动消失。
- [ ] 待办数量随待办消解实时更新。
- [ ] 无待办时显示“暂无待办”，不补充其他提醒或营销内容。
